# dyar-load-testing

أداة اختبار تحميل/سعة (load & capacity testing) لتطبيق **dyar.app**، مكتوبة بـ Node.js
نقيّة بلا أي تبعيات خارجية (تستخدم `worker_threads` + `https` المدمجة فقط).

النموذج: **closed-loop / think-time = 0** — كل "مستخدم افتراضي" يطلق طلباً، ينتظر الرد كاملاً،
ثم يطلق التالي فوراً، طوال مدة المرحلة. هذا يعطي **أقصى إنتاجية مستدامة** ويترجمها إلى **مستخدمين/الساعة**.

## التشغيل

```bash
# اختبار سريع للتحقق
node src/loadtest.js --target https://dyar.app/ --stages 5,25,100 --duration 4

# اختبار سعة متدرّج كامل
node src/loadtest.js \
  --target https://dyar.app/ \
  --stages 10,25,50,75,100,150,200,300 \
  --duration 8 --cooldown 2 \
  --reqs-per-user 8
```

## المعاملات

| المعامل | الافتراضي | الوصف |
|---|---|---|
| `--target` | `https://dyar.app/` | العنوان المُختبَر |
| `--stages` | `1,5,10,...,800` | قائمة مستويات الـconcurrency (مفصولة بفواصل) |
| `--duration` | `8` | مدة كل مرحلة بالثواني |
| `--cooldown` | `2` | فترة تبريد بين المراحل بالثواني |
| `--reqs-per-user` | `8` | عدد الطلبات في جلسة المستخدم الواحدة (لحساب مستخدمين/الساعة) |
| `--error-abort` | `0.10` | إيقاف الزيادة إذا تجاوزت نسبة الأخطاء هذا الحد |
| `--threads` | كل الأنوية | عدد خيوط العمل |
| `--out` | `results/run-<ts>.json` | مسار تقرير JSON |

## المخرجات

- جدول لكل مرحلة: req/s، نسبة الأخطاء، زمن الاستجابة (p50/p95/p99/max)، الإنتاجية (Mbps).
- **الذروة المستدامة** وتحويلها إلى **مستخدمين/الساعة**.
- تقرير JSON كامل في `results/`.

## النتائج والتقرير

انظر **[`results/REPORT.md`](results/REPORT.md)** للتحليل الكامل والخلاصات والتحذيرات المنهجية المهمة
(أبرزها أن dyar.app خلف Fastly CDN، وأن قياس مصدر واحد يعطي **حدّاً أدنى** لا السعة القصوى).
