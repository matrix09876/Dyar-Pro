# Dyar — خارطة الطريق (Roadmap)

منظومة سوبر آب توصيل تنافس Wolt و Haat.delivery. البناء على مراحل، كل
مرحلة قابلة للتشغيل والتسليم.

## المرحلة 0 — التأسيس ✅ (جارية الآن)
- [x] تصحيح سياق المشروع (`CLAUDE.md`) — ديار = توصيل وليس عقارات.
- [x] نموذج البيانات (`docs/DATA-MODEL.md`).
- [x] هيكل الـ monorepo.
- [ ] خلفية Firebase: قواعد الأمان + هيكل Cloud Functions + الفهارس.

## المرحلة 1 — لوحة التحكم (Dashboard) 🎯 الأولوية
React + Vite + TS + Tailwind، RTL، Firebase.
- [ ] مصادقة الإدارة + حماية المسارات.
- [ ] الواجهة العامة (KPIs + رسوم: الطلبات/الإيرادات/المستخدمون).
- [ ] إدارة الطلبات (قائمة لحظية + تفاصيل + تغيير الحالة + تعيين سائق).
- [ ] إدارة المتاجر (موافقة/تعليق + القوائم/المنتجات + العمولة).
- [ ] إدارة السائقين (موافقة على الوثائق + الحالة + الأرباح).
- [ ] إدارة المستخدمين (بحث/حظر/محفظة).
- [ ] الأصناف، المدن/المناطق، العروض والكوبونات.
- [ ] التقارير المالية والتسويات. الإعدادات العامة.

## المرحلة 2 — تطبيق السائق (`dyar.driver`)
Flutter. تسجيل + رفع وثائق، أونلاين/أوفلاين، استقبال المهام، الخرائط
والملاحة، التقاط/تسليم، الأرباح، الدردشة.

## المرحلة 3 — تطبيق التاجر (`dyar.partner`)
Flutter. استقبال الطلبات لحظيًا + قبول/رفض، إدارة القائمة والتوفر،
العروض، التقارير، الدردشة مع السائق/الزبون.

## المرحلة 4 — تطبيق المستخدم (`dyar.user`)
Flutter. تصفّح المتاجر/الخدمات، البحث والتصفية، السلة، الدفع
(Stripe/PayPal/محفظة/نقدًا)، التتبّع الحي، التقييم، المفضلة، الحساسية.

## المرحلة 5 — التكاملات والإطلاق
- مفاتيح Stripe/PayPal الحقيقية + اختبار الدفع End-to-End.
- Google Maps الحقيقي. إشعارات FCM لكل تطبيق.
- تجهيز متجر آبل وجوجل (أيقونات، لقطات، أوصاف، سياسات).
- اختبار قبول كامل ثم النشر.

## ما نتفوّق به على المنافسين (Differentiators)
- خدمات + توصيل + نقل في تطبيق واحد (ليس فقط طعام).
- قسم الحساسية والمفضلة الذكية.
- لوحة تحكم تشغيلية قوية (تعيين سائق ذكي، تحليلات حية).
- نظام أكشاك (Kiosk) للفروع كما في ديار الحالي.
