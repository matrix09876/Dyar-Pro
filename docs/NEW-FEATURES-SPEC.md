# 🧾 مواصفات الإضافات الجديدة + عقد البيانات (13/06/2026)

شرح كل إضافة وربطها بلوحة التحكم وتطبيق البزنس والعقد البرمجي.
التصميم يُبنى في Figma (Pro V10) عبر الوكلاء؛ هذا المستند مصدر الحقيقة
للكود التالي.

## 1) 🖨️ طابعة المطبخ (KOT) — تطبيق البزنس
**الوظيفة**: طباعة تذكرة الطلب للمطبخ تلقائيًا أو يدويًا.
- **شاشات**: P9 معاينة التذكرة (KOT) · P10 إعدادات الطابعة.
- **العقد**: `stores/{id}/config/printer` =
  `{ enabled, autoPrint:bool, paperSize:'58'|'80', copies:int,
     cashierCopy:bool, connection:'bluetooth'|'lan', deviceId }`.
- **التنفيذ التقني**: الطباعة من جهاز المتجر عبر `esc_pos_utils` +
  `print_bluetooth_thermal`/`network` (Flutter) — توليد ESC/POS من
  بيانات الطلب. تُطبع عند `status=accepted` إن `autoPrint`، أو بزر يدوي.
- **اللوحة**: عمود/مفتاح "طابعة" في صفحة المتاجر + سجل طباعة في Logs.

## 2) 🥫 صور الإضافات الصغيرة (Modifier icons)
**الوظيفة**: أيقونة/صورة دائرية 24px لكل إضافة (كاتشوب/طحينة/خيار/
فلفل/بصل/ثوم…) تظهر بجانب الصنف في الطلب — فهم التخصيص بنظرة.
- **العقد**: توسيع `stores/{id}/options/{group}.choices[]` بحقل
  `icon?: string` (مفتاح أيقونة مدمجة) أو `imageUrl?: string`.
  مكتبة أيقونات مدمجة: ketchup/tahini/cucumber/pepper/onion/garlic/
  cheese/spicy/no-X (رمادي مشطوب).
- **يظهر في**: تطبيق البزنس (تفاصيل الطلب + تذكرة KOT)، وتطبيق الزبون
  (item_sheet عند اختيار الإضافات)، واللوحة (تفاصيل الطلب).

## 3) 🛎️ الحجوزات Booking-grade — عمودي جديد كامل
**الوظيفة**: منافس Booking.com — 5 فئات حجز.
- **شاشات (صفحة Figma جديدة)**: BK1 Hub · BK2-4 فنادق · BK5-6 سيارات ·
  BK7 بيوت · BK8 فعاليات · BK9 طاولة+خريطة · BK10 تأكيد.
- **العقد**: `bookings/{id}` موسّع:
  `{ type:'table'|'hotel'|'car'|'house'|'event',
     customerUid, vendorId, status, fee, currency:'ILS',
     // فنادق/بيوت:
     checkIn?, checkOut?, guests?, rooms?, roomType?,
     // سيارات:
     pickupAt?, dropoffAt?, pickupLoc?, carClass?, insurance?,
     // فعاليات:
     eventId?, tickets?:[{tier,qty}],
     // طاولة:
     slot?, partySize?, tableId?,
     location?:{lat,lng,line}, qrCode?, createdAt }`.
- **مزوّدون**: `vendors/{id}` (فنادق/تأجير/شقق/منظّمو فعاليات) —
  نوع `vendorType` + غرف/سيارات/وحدات كمجموعات فرعية بأسعار وتوفّر.
- **الخادم**: `createBooking` (موجودة) توسَّع لكل نوع + حساب السعر
  server-side + `bookings` reminders (موجودة).
- **اللوحة A12 Bookings**: تبويبات بالنوع (طاولة/فندق/سيارة/بيت/فعالية)
  + إدارة المزوّدين والتوفّر + العمولة لكل نوع.
- **الخرائط**: خريطة الموقع ومخطط الطاولات تستهلك مفتاح Maps (البند 4
  في KEYS-RUNBOOK).

## 4) 🎨 هوية كل خدمة + راحة الواجهة
- **هوية الخدمة**: `config/serviceIdentity.{key}` =
  `{ primary, secondary, gradient:[from,to], icon }` — اللوحة تضبطها،
  والتطبيق يقرأها (services_screen يستعملها بدل التدرجات الثابتة).
- **راحة الواجهة**: تباعد 16-20px، تسلسل بصري Black/Muted، المطاعم
  والخدمات أولوية أولى في الرئيسية، كلمات تسويقية جاذبة، تباين AA.

## 5) الربط الكامل
كل ما سبق **يُدار من لوحة التحكم** (طابعة/إضافات/مزوّدو الحجز/العمولات/
هوية الخدمات) و**ينعكس لحظيًا** على تطبيق البزنس والزبون عبر Firestore
(مصدر حقيقة واحد) — نفس معمارية ديار القائمة.

> لأنهما الأقرب للإطلاق، ثم عمودي الحجوزات).
