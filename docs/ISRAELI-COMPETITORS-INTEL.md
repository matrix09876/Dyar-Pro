## 1) תן ביס / 10bis — اللاعب المحوري في نمط منفعة الوجبات

**كيف يعمل (How it works)**: 10bis ليس مجرد تطبيق توصيل — هو **منصة منفعة
وجبات للموظفين (Meal-Benefit)**. صاحب العمل يخصّص لكل موظف **ميزانية
وجبات** (يومية أو شهرية)، والموظف ينفقها عبر التطبيق: توصيل، **استلام ذاتي
(איסוף עצמי / pickup)**، أو **دفع داخل المطعم (dine-in)** بـ بطاقة 10bis
المغناطيسية أو **كود/باركود يُولَّد في التطبيق** يقدّمه للكاشير. تُحوَّل
قيمة الوجبة لفاتورة صاحب العمل، وتُحتسب كـ **منفعة بمعادل نقدي (הטבה
בשווה כסף)** خاضعة للضريبة على الموظف.

### آلية الميزانية (الجوهر — انسخها بدقة)
- **يومي أو شهري**: مثال شائع **25 ₪/يوم** أو **500 ₪/شهر** — يضبطه صاحب
  العمل لكل موظف/فريق.
- **أيام العمل فقط (اختياري)**: صاحب العمل يقرر هل الاستخدام **لساعات/أيام
  الدوام فقط** أم يُسمح بالفائض في الوقت الحر.
- **Use-it-or-lose-it**: الرصيد غير المستخدم **لا يُرحَّل للشهر التالي**
  (في النمط اليومي، رصيد اليوم ينتهي بنهاية اليوم) — ما يحفّز الطلب اليومي.
- **الفائض (Overage)**: إن تجاوزت الوجبة الميزانية، الموظف يدفع الفرق
  نقدًا أو ببطاقته الائتمانية الشخصية في نفس المعاملة.
- **عمولة التاجر**: ~**7%–12%** من سعر الوجبة (مصدر: ويكيبيديا العبري).

### الميزات البارزة (10bis)
- **3 أنماط استهلاك**: توصيل · استلام ذاتي (pickup) · **دفع في المطعم
  بكود/بطاقة** — الـ pickup والـ dine-in جوهريان (الموظف قرب مكتبه).
- **+10,000 مطعم/مقهى/متجر طعام**؛ الإنفاق يمتد لـ **سوبرماركت، مخابز،
  ملاحم، حتى اشتراكات جيم** (الميزانية أوسع من المطاعم).
- **فلاتر**: نباتي / خالٍ من الغلوتين / **كوشير** + فلتر **توصيل مجاني**.
- **ادخار رصيد** ("ארוחות"/coupons): تجميع رصيد لوجبة أكبر لاحقًا (ضمن قيود
  صاحب العمل) — نمط شائع للطلبات الجماعية المكتبية.
- **لا حاجة لبطاقة فعلية**: التطبيق وحده يكفي للدفع (كود/QR).

**نقطة ضعف يهاجمها Wolt صراحةً** (مدير Wolt إسرائيل): "الاضطرار للطلب قبل
ساعة محددة صباحًا مع الزملاء" و"تقديم **كود رقمي في كل مرة** بالمطعم" —
يعتبرها Wolt ممارسات بالية. **(فرصة لديار: تجربة منفعة أكثر سلاسة.)**

## 2) Cibus / Pluxee (Sodexo→Pluxee) — بطاقة المنفعة المنافسة

**كيف يعمل**: Cibus محفظة منافع رقمية. الموظف يحمل **رصيد منفعة** يُنفقه
بـ **توليد كود دفع في التطبيق** يُقدَّم في المطعم/المتجر، أو **عبر تطبيقات
شريكة** — أبرزها **Wolt** (يدفع داخل Wolt برصيد Cibus). لا حاجة للبطاقة
الفعلية؛ الدفع من الموبايل بكود شخصي آمن.

### الميزات البارزة (Cibus / Pluxee)
- **+10,500 مطعم بلا رسوم توصيل** + سوبرماركت + صيدليات + متاجر أونلاين.
- **تكامل مع Wolt**: حامل Cibus يدفع داخل Wolt برصيده — توصيل مكتبي سريع.
  (من لا يملك بطاقة: يتواصل عبر دردشة Wolt باسم شركته للانضمام.)
- **توليد كود دفع + سجل معاملات + رصيد لحظي** داخل التطبيق.
- **لوحة صاحب العمل**: اختيار نوع المنفعة، توقيت منحها، المبلغ + منافع
  إضافية (هدية عيد ميلاد، لياقة، إحالة). **~6,000 شركة** على Cibus.
- **استخدام في الخارج** (سفر) مدعوم.

## 7) العنوان الكبير — منفعة الوجبات للشركات (Cibus/10bis) = أكبر فجوة لديار في إسرائيل

### لماذا هذه أهم فجوة (وليست مجرد ميزة)
- ~**17%** من كل طلبات المطاعم أونلاين تمرّ عبر **10bis** وحده، و**90%** من
  سوق بطاقة الغداء بيد لاعبَين. الموظف الإسرائيلي **لا يطلب بماله** بل
  **بميزانية صاحب العمل**. ديار بلا منفعة وجبات = ديار بلا شركات الجليل
  (بلديات، مصانع، مستشفيات، شركات هايتك عربية صاعدة) — وهي شريحة **مهمَلة
  تمامًا** من المنافسين بالعربية.
- التموضع لديار: **«ميزانية وجبات / بطاقة وجبات» محلية بالعربية** لأرباب
  العمل في الجليل والمثلث — أول من يقدّمها بالعربية، فوق سوبر-آب يضمّ
  بالفعل طعامًا + بقالة + صيدلية + خدمات.

### مقترح ملموس: «ديار وجبات / Dyar Meals» (عقد بيانات + ربط اللوحة والبزنس)

> ملاحظة يقين: **آليات الضريبة الدقيقة ونِسب الإعفاء في إسرائيل تتغيّر
> وتحتاج محاسبًا محليًا**؛ ما يلي **هيكل منتج** لا استشارة ضريبية. تكامل
> تسوية Cibus/Wolt الفعلي يتطلب **اتفاقية مزوّد** (غير مؤكد توفّرها لطرف
> ثالث) — لذا نبني منفعتنا الخاصة **وأيضًا** نقبل Cibus كوسيلة دفع متى أمكن.

**(أ) المنظمة وقواعد الميزانية** — `config` + جذر جديد:
```
organizations/{orgId}: {
  name, billingEmail, taxId,
  adminUids: [],                 // مدراء الموارد البشرية بالشركة
  cityIds: [],                   // مدن التشغيل
  invoiceCycle: 'monthly',
  status: 'active'|'suspended',
  // قواعد صرف لكل فريق/مجموعة:
  budgetRules: [{
    label,                       // «فريق المبيعات»، «الكل»
    memberUids: [],
    amount,                      // 25 (يومي) أو 500 (شهري)
    period: 'daily'|'monthly',
    rollover: false,             // Use-it-or-lose-it (الافتراضي false)
    days: [0..6],                // أيام السماح (دوام)
    hours: { from, to },         // ساعات الغداء (اختياري)
    allowedMerchantTypes: [],    // restaurant|grocery|pharmacy…
    allowedMerchantIds: [],      // قائمة بيضاء (كوشير/حلال معتمَد)
    certification: 'kosher'|'halal'|null, // حصر بالتصديق
    allowOverage: true           // يكمّل الموظف الفرق
  }]
}
```

**(ب) حساب/رصيد الموظف** — مرتبط بـ `users/{uid}`:
```
mealAccounts/{uid}: {
  orgId, ruleLabel,
  balance,                       // الرصيد المتاح الآن
  period: 'daily'|'monthly',
  resetsAt,                      // وقت التصفير القادم
  savedCoupons: [{amount, expiresAt}],  // ادخار رصيد (IL-8)
  ledger: [{ts, type:'grant'|'spend'|'expire'|'overage', amount, orderId}]
}
```

**(ج) الدفع وscan-to-pay وdine-in** — توسيع نموذج الطلب:
```
orders/{id}.payment: {
  method: 'meal_budget'|'cibus'|'card'|'cash'|…,
  mealAccountId?,
  budgetApplied,                 // كم خُصم من الميزانية
  overagePaid,                   // الفرق الذي دفعه الموظف
  overageMethod: 'card'|'cash'
}
// dine-in/pickup بكود:
posPayments/{id}: {
  storeId, uid, code,            // كود/QR يولّده تطبيق الزبون
  amount, budgetApplied, overagePaid,
  status: 'pending'|'paid'|'expired',
  scannedByStaffUid?, ts
}
```

**(د) دوال Cloud Functions (server-side، القاعدة الإلزامية 3)**
- `grantMealBudgets` (مجدولة): تطبّق `budgetRules` يوميًا/شهريًا، تصفّر
  المنتهي (Use-it-or-lose-it)، تسجّل في `ledger`.
- `payWithMealBudget`: تتحقق من القاعدة (يوم/ساعة/متجر مسموح/تصديق) قبل
  الخصم؛ تحسب الفائض وتحصّله؛ تكتب في `ledger`.
- `generatePosCode` / `redeemPosCode`: scan-to-pay داخل المطعم — الزبون
  يولّد كود/QR، الكاشير يمسحه (تطبيق البزنس)، يُخصم من الميزانية + يُحصّل
  الفائض.
- `chargeCibus` (G6 المطوّرة): قبول بطاقة Cibus كوسيلة دفع عبر مزوّد
  المنفعة (يتطلب اتفاقية).
- `closeOrgInvoice` (شهرية): تجمّع إنفاق الشركة → فاتورة واحدة + **تقرير
  منفعة بمعادل نقدي** لكل موظف (للأجور والضريبة).

**(هـ) لوحة التحكم (admin)** — قسم **«الشركات / Dyar Meals»**:
- إدارة `organizations`: إضافة شركة، مدراء، مدن.
- محرّر `budgetRules` المرئي (مبلغ/فترة/أيام/ساعات/متاجر مسموحة/تصديق).
- **فوترة**: دورة شهرية، تنزيل فاتورة + CSV تقرير المنفعة الضريبي لكل موظف.
- تقارير: إنفاق الشركة، أكثر المتاجر، استخدام مقابل المخصّص (ميزانية مهدورة).

**(و) تطبيق البزنس (partner)** — جانب التاجر:
- **شاشة scan-to-pay**: الكاشير يمسح كود/QR زبون → يرى المبلغ المخصوم من
  المنفعة والفائض المطلوب نقدًا/بطاقة → تأكيد.
- شارة «يقبل Dyar Meals / Cibus» على ملف المتجر + فلتر اكتشاف للزبون.
- تقرير تسوية: كم من مبيعاته جاء من ميزانيات الشركات (للتسوية والعمولة).

**(ز) تطبيق الزبون (user)**:
- **بطاقة «ميزانيتي اليوم»** على الرئيسية (رصيد + وقت التصفير + IL-11).
- وسيلة دفع «ميزانية الوجبات» + «Cibus» في الدفع، مع عرض الفائض بوضوح.
- زر **«ادفع في المطعم»** يولّد QR (dine-in/pickup) — يقفز فوق احتكاك
  «الكود الرقمي» الذي يشكو منه Wolt: كود تلقائي بنقرة بلا إدخال يدوي.

## 8) أفضل ما يُضاف (مرتّب بالأولوية) — خاص بالسوق الإسرائيلي

1. **(P0) ديار وجبات — حساب شركة + ميزانية يومية/شهرية** (IL-1, IL-2):
   عقد `organizations` + `mealAccounts` + `grantMealBudgets`. **يفتح سوق
   الشركات بأكمله** — المفتاح الإسرائيلي الأهم.
2. **(P0) Scan-to-pay + استلام ذاتي + dine-in برصيد المنفعة** (IL-3):
   `posPayments` + `generate/redeemPosCode` + شاشة كاشير في البزنس. معظم
   استهلاك المنفعة ليس توصيلًا.
3. **(P1) قبول Cibus كوسيلة دفع** (IL-9): مكسب فوري — موظفو الشركات يطلبون
   من ديار قبل أن نبني منفعتنا (يتطلب اتفاقية مزوّد).
4. **(P1) سياسات صرف دقيقة + متاجر مسموحة/تصديق** (IL-5): أيام/ساعات/فريق +
   حصر كوشير/حلال — يربط نمط المنفعة بفلتر كوشير/حلال المصمَّم أصلًا.
5. **(P1) فوترة شهرية موحّدة + تقرير منفعة ضريبي** (IL-6): شرط تبنّي أي
   شركة إسرائيلية (يلزم تدقيق محاسب محلي للأرقام/الإعفاءات).
6. **(P1) دفع الفائض في نفس المعاملة** (IL-4): تجربة لا تنكسر عند تجاوز
   السقف.
7. **(P2) Tap-to-Pay/بطاقة موظف بلا كود يدوي** (IL-7): تفوّق مباشر على
   شكوى «الكود في كل مرة».
8. **(P2) ادخار رصيد + Cashback + لوحة «ميزانيتي»** (IL-8, IL-10, IL-11):
   احتفاظ يومي ومتوسط سلة أعلى.
