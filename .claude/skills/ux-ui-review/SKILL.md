# UX/UI Review — مراجعة تجربة وواجهة ديار

راجع تجربة وواجهة تطبيقات ديار من منظور المستخدم العربي على الموبايل.
إن توفّرت لقطة/شاشة فعلية حلّلها بصرياً؛ وإلا راجع الكود/الوصف. رتّب الملاحظات
حسب الأثر على المستخدم.

## 1. تجربة المستخدم (UX) — الأهم

- [ ] **وضوح المهمة**: هل يفهم المستخدم ماذا يفعل في أول 3 ثوانٍ؟
- [ ] **أقل عدد خطوات** لإنجاز المهمة الأساسية (بحث عن عقار → تفاصيل → حجز).
- [ ] **تغذية راجعة فورية**: حالات تحميل، تأكيد نجاح، رسائل خطأ مفهومة بالعربية.
- [ ] **منع الأخطاء**: تأكيد قبل الإجراءات الحسّاسة (إلغاء حجز، دفع، حذف).
- [ ] **حالات فارغة (Empty states)** مفيدة لا شاشة بيضاء (لا نتائج بحث، لا طلبات).
- [ ] **مسارات واضحة للرجوع** والخروج من كل شاشة.
- [ ] تباين أدوار التطبيقات منطقي (user يبحث ويحجز / partner يدير / driver ينفّذ).

## 2. RTL والعربية (حرِج)

- [ ] التخطيط ينعكس صحيحاً في RTL (المحاذاة، الأيقونات الاتجاهية، التنقّل).
- [ ] لا نص إنجليزي مقحم وسط واجهة عربية دون داعٍ.
- [ ] الأرقام والعملة (ريال/دينار…) والتواريخ بالصيغة المحلية الصحيحة.
- [ ] الخط العربي واضح ومقروء بأحجام كافية، لا تقطيع للحروف.
- [ ] النصوص الطويلة لا تسبب overflow؛ تُلتفّ أو تُقصّ بأناقة.

## 3. الإتاحة (Accessibility)

- [ ] أهداف اللمس ≥ 48×48dp.
- [ ] تباين ألوان كافٍ (نص/خلفية ≥ 4.5:1).
- [ ] دعم قارئ الشاشة: `Semantics`/labels على الأيقونات والأزرار.
- [ ] يحترم حجم الخط من النظام (`textScaleFactor`) دون كسر التخطيط.
- [ ] لا تعتمد على اللون وحده لنقل المعنى.

## 4. الاتساق البصري (مع Dyar Ultra UI)

- [ ] الألوان/المسافات/الأنصاف/الخطوط من نظام التصميم لا قيم عشوائية.
- [ ] الأزرار/البطاقات/الحقول متّسقة عبر الشاشات والتطبيقات الأربعة.
- [ ] تسلسل بصري واضح (العنصر الأهم أبرز).
- [ ] أيقونات متّسقة الأسلوب والحجم.

## 5. أنماط الموبايل

- [ ] التنقّل السفلي/العلوي واضح ومتوقّع.
- [ ] احترام المناطق الآمنة (`SafeArea`) والـ notch وأزرار النظام.
- [ ] لوحة المفاتيح لا تغطّي الحقول؛ تمرير عند الحاجة.
- [ ] إيماءات متوقّعة (سحب للتحديث، سحب للحذف حيث يناسب).
